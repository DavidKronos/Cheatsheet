Closure

function counter() {
  let count = 0;         // closed-over var
  return {
    inc: () => ++count,
    get: () => count
  };

A closure is a function that remembers its lexical scope even when executed outside it.

Classic var Loop Bug & Fix

// ❌ Bug — logs 3, 3, 3

  setTimeout(() => console.log(i), 0);
}

// ✅ Fix 1 — use let (block scope)
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);

    console.log(j), 0))(i);
}

Frequently Asked Q&A
Click to expand answers
Q What is the difference between null and undefined? ▼

undefined means a variable has been declared but not yet assigned a value. It's the default value of uninitialized variables, function parameters not provided, and missing object properties.

null is an intentional assignment indicating "no value". It must be explicitly set by the programmer. typeof null === 'object' is a historical JS bug.

let x;           // undefined — not assigned
let y = null;    // null — intentionally empty
x == y;          // true (loose)
x === y;         // false (strict)
Q Explain Event Delegation. ▼

Event delegation uses event bubbling to handle events at a parent level rather than attaching listeners to each child. This is more efficient for dynamic lists.

// ❌ Bad — listener on every item
document.querySelectorAll('li').forEach(
  el => el.addEventListener('click', handler)
);

// ✅ Good — one listener on parent
document.querySelector('ul')
  .addEventListener('click', (e) => {
    if (e.target.matches('li'))
      handler(e.target);
  });
Q What is debounce vs throttle? ▼

Debounce: Waits until the user stops triggering events for N ms before executing. Use for search input, resize handlers.

Throttle: Executes at most once per N ms no matter how often triggered. Use for scroll, mouse-move events.

function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

function throttle(fn, limit) {
  let last = 0;
  return (...args) => {
    if (Date.now() - last >= limit) {
      last = Date.now();
      fn(...args);
    }
  };
}
Q What is a WeakMap / WeakSet and when would you use them? ▼

WeakMap and WeakSet hold weak references to objects. When the object is garbage-collected, its entry is automatically removed — preventing memory leaks.

Use WeakMap for: private data per object, caching DOM node metadata, storing state associated with external objects you don't own.

const cache = new WeakMap();

function process(node) {
  if (cache.has(node)) return cache.get(node);
  const result = expensiveCompute(node);
  cache.set(node, result);
  return result;
}
Q What is the Temporal Dead Zone (TDZ)? ▼

The TDZ is the time between entering a block scope and the point where a let or const declaration is actually evaluated. Accessing a variable in its TDZ throws a ReferenceError, unlike var which returns undefined.

console.log(x); // undefined — var hoisted
var x = 5;

console.log(y); // ReferenceError — TDZ!
let y = 5;

Scenario-Based Questions
Common real-world problem patterns
Scenario — Deep Clone

"How would you deep-clone an object without using libraries?"

For simple JSON-serializable objects: JSON.parse(JSON.stringify(obj)). Limitations: loses undefined, functions, Dates, circular refs. Better: structuredClone(obj) (modern browsers) — handles circular refs, Dates, Maps, Sets.

Scenario — Memory Leak

"What are common memory leaks in JavaScript?"

Global variables never garbage-collected; event listeners not removed when elements are removed; closures holding large data; timers (setInterval) referencing removed DOM; detached DOM nodes held by JS references.

Scenario — Output Question

What does this output?

console.log(1 + '2');  // "12" — number coerced to string
console.log('3' - 1);  // 2  — string coerced to number
console.log(true + true); // 2  — bool to number
console.log([] + []);   // "" — both to empty string
console.log({} + []);   // "[object Object]"

Q What is BEM naming convention? ▼

BEM = Block__Element--Modifier. It creates a flat, predictable class structure that avoids specificity wars.

/* Block */         .card {}
/* Element */       .card__title {}

Q Explain CSS custom properties (variables). ▼

CSS variables (custom properties) are inherited and can be updated with JavaScript. They cascade and scope to the element they're defined on.

:root {
  --primary: #3B82F6;
  --spacing: 16px;
}

.button {
  background: var(--primary);
  padding: var(--spacing);
  /* Fallback: */
  color: var(--text-color, black);
}

// Update via JS
document.documentElement.style
  .setProperty('--primary', '#EF4444');

Merge vs Rebase — The Key Difference

── MERGE ──  Preserves history, creates merge commit
A — B — C (main)          A — B — C (main)
         \            →            \         \
          D — E (feat)              D — E ─── M  ← merge commit

── REBASE ──  Linear history, rewrites commits
A — B — C (main)          A — B — C (main)
         \            →                     \
          D — E (feat)                       D' — E'  ← replayed

⚠️ Never rebase shared/public branches — it rewrites history that others depend on.

Git Interview Q&A
Q What's the difference between git fetch and git pull? ▼

git fetch downloads changes from remote but does NOT modify your working tree or current branch. git pull = git fetch + git merge — it downloads and immediately merges into your current branch. Use fetch when you want to inspect changes before integrating.

Q What is git stash and when would you use it? ▼

Stash temporarily saves uncommitted changes so you can switch branches or pull without losing work. Typical scenario: you're mid-feature when an urgent bug report comes in — stash your work, fix the bug on another branch, then pop the stash to resume.

git stash                  # save current work
git stash list             # see all stashes
git stash apply stash@{1}  # apply specific stash
git stash drop stash@{0}   # delete a stash
git stash pop              # apply latest + delete
Q How do you resolve a merge conflict? ▼

Git marks conflicts in the file with conflict markers. You edit the file to resolve, then stage and commit.

# In the conflicted file:
<<<<<<< HEAD
  your version
=======
  incoming version
>>>>>>> feature-branch

# Steps:
1. Open conflicted file, edit to desired state
2. git add <file>         # mark as resolved
3. git commit             # complete the merge
